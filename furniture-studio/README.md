# Мастерская мягкой мебели — сайт + CMS

Production-ready сайт мебельной мастерской (диваны на заказ, кресла) с админкой на Next.js App Router + Supabase.

## Стек

Next.js 14 (App Router) · TypeScript · Tailwind CSS · Supabase (DB, Storage, Auth) · Vercel

---

## 1. Как запустить локально

```bash
npm install
cp .env.example .env.local
# заполните .env.local значениями из вашего проекта Supabase — см. раздел 2 ниже
npm run dev
```

Сайт откроется на `http://localhost:3000`, админка — на `http://localhost:3000/admin`.

---

## 2. Как подключить Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. В **Project Settings → API** скопируйте:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (⚠️ секрет, никогда не публикуйте и не коммитьте)
3. Вставьте значения в `.env.local` (локально) и в переменные окружения Vercel (для продакшена).

## 3. Какие environment variables нужны

См. `.env.example`. Кратко:

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ, используется в браузере и на сервере, подчиняется RLS |
| `SUPABASE_SERVICE_ROLE_KEY` | Полный доступ к БД в обход RLS. Только server-side. Никогда не коммитить. |
| `NEXT_PUBLIC_SITE_URL` | Публичный домен сайта — используется в metadata, sitemap, OG |
| `REVALIDATE_SECRET` | Секрет для защиты внутренних вызовов ревалидации (задел на будущее) |

## 4. Как запустить миграции

Миграция лежит в `supabase/migrations/0001_init.sql` и содержит: все таблицы, индексы, constraints, триггеры `updated_at`, RLS-политики и Storage-бакеты (`works`, `site`) с политиками доступа.

**Вариант А — через Supabase CLI (рекомендуется):**

```bash
npx supabase login
npx supabase link --project-ref <ваш-project-ref>
npx supabase db push
```

**Вариант Б — вручную:**

Откройте **Supabase Dashboard → SQL Editor**, вставьте содержимое `supabase/migrations/0001_init.sql` и выполните.

После применения миграции в БД уже будут:
- категории «Диваны» и «Кресла»;
- пустые записи `home_sections` для всех блоков главной/about (тексты по умолчанию подставляются кодом, пока админ их не заполнит);
- одна строка `site_settings`.

Если Storage-бакеты `works`/`site` не создались автоматически (зависит от прав вашего проекта) — создайте их вручную в **Dashboard → Storage**: оба **Public**.

## 5. Как создать первого администратора

Supabase Auth не создаёт пользователей автоматически — сделайте это один раз вручную:

1. **Dashboard → Authentication → Users → Add user**.
2. Укажите email и пароль, отметьте **Auto Confirm User**.
3. Этими данными входите на `/admin/login`.

Регистрация через сайт отсутствует намеренно — админка закрытая, для одного администратора (см. `ARCHITECTURE.md`, раздел Auth).

## 7. Как задеплоить на Vercel

1. Импортируйте репозиторий в [vercel.com/new](https://vercel.com/new).
2. В **Settings → Environment Variables** добавьте те же переменные, что в `.env.local` (см. раздел 3), для **Production** и **Preview**.
3. Задеплойте. Vercel сам определит Next.js и настроит билд (`next build`).
4. Убедитесь, что миграция Supabase уже применена (раздел 4) — сайт ожидает существующую схему БД.

## 8. Где находится публичный сайт

Корень домена: `/`, `/works`, `/works/[slug]`, `/about`, `/contacts`.

## 9. Где находится админка

`/admin` (редирект на `/admin/login`, если не авторизованы).

## 10. Как добавить новую работу

1. Зайдите в `/admin/works/new`.
2. Заполните название (slug сгенерируется автоматически, можно поправить), выберите категорию, при необходимости — описание и характеристики.
3. Сохраните — вас перенаправит на страницу редактирования, где появится блок «Фотографии».
4. Загрузите одну или несколько фотографий (JPEG/PNG/WebP, до 8 МБ каждая).
5. Отметьте одну из фотографий как обложку («Сделать обложкой») — иначе используется первая загруженная.
6. При необходимости отметьте «Показывать в Избранных работах», чтобы работа попала в соответствующий блок на главной.

Работа со статусом «Опубликовано» сразу появляется на `/works` и, если отмечена как Featured, на главной.

## Известные ограничения (осознанные компромиссы)

Ничего не выдаётся за работающее, если это не так:

- **Rate limit формы заявки** — реализован в памяти процесса (`lib/utils/rate-limit.ts`). На serverless-платформах (Vercel) состояние не гарантированно переживает между вызовами разных инстансов функции — это ограничение задокументировано, а не скрыто. Для строгой защиты от спама в проде стоит подключить Upstash Redis или аналог — это не было частью согласованного стека.
- **Порядок фотографий** реализован кнопками «вверх/вниз», а не drag-and-drop — сознательный выбор в пользу надёжности и меньшего количества клиентского JS (см. `ARCHITECTURE.md`, Performance).
- **Один администратор** — регистрации через UI нет, пользователь создаётся вручную в Supabase Dashboard (см. раздел 5). Если нужно несколько ролей — потребуется таблица `admin_users` с ролями, сейчас не реализована, т.к. не была запрошена.

## Перед развёртыванием

1. Примените все миграции из `supabase/migrations` к той же базе Supabase, которую использует Vercel.
2. Особенно важны `0002_redesign_fields.sql` (цена, изображение категории, динамическое меню) и `0003_ensure_menu_defaults.sql`.
3. Убедитесь, что Vercel использует `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` именно этой базы.
4. После изменения переменных окружения выполните новое production deployment.

### Проверка админской записи

Если сохранение возвращает ошибку, новая версия показывает диагностическое сообщение. Например, при отсутствии новой колонки будет явно предложено применить миграцию, а при проблеме с правами — проверить авторизацию/RLS.
